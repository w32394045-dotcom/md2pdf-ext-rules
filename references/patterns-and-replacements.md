# 正则与替换串：两套 `$` 语义、配方、雷区

扩展里的正则有**两套完全不同的替换语义**，混用就是事故现场。先分清你在写哪一类。

---

## 1. 先记住：JSON 里反斜杠要双写

JSON 字符串里 `\` 是转义符，所以正则里的 `\d` 必须写成 `\\d`：

| 想写 | JSON 里写成 |
|---|---|
| `\d+` | `"\\d+"` |
| `\.` | `"\\."` |
| `[^\]]` | `"[^\\]]"` |
| `\u4e00` | `"\\u4e00"`（注意：JSON 也可以吃 `\u4e00`，但那就变成真汉字了） |

单引号在 JSON 里非法；模板里的 HTML 属性统一用 `\"` 转义的双引号。

---

## 2. 两条执行路径（决定了 `$` 含义）

```text
原文
 ├─ preProcess：String.replace(pattern, replacement)   ← 原生 JS 语义，一条条全文替换
 ├─ Markdown 块级解析
 │    └─ 行内解析：代码/公式/HTML 标签先被摘成占位符
 │         └─ customSyntax inline：工具自己的求值器       ← 工具自己实现的 $ 语法
 └─ 围栏解析：customSyntax block 的模板插入 $content      ← 只认 $content，别的 $ 原样
```

**关键差异**：

| 写法 | `preProcess` 的 `replacement` | `customSyntax.inline` 的 `replacement` |
|---|---|---|
| `$1`…`$9` | 第 N 个捕获组；**组不存在时原样留下 `$N` 这两个字符** | 第 N 个捕获组；**组不存在时变成空串** |
| `$10` | 第 1 组 + 字面 `0`（组数不足 10 时） | 第 1 组 + 字面 `0`（同） |
| `$0` | **不是特殊写法**，原样输出 `$0` | **整个匹配** |
| `$&` | **整个匹配** | **整个匹配** |
| `$$` | 字面 `$` | 字面 `$` |
| 美元符后紧跟一个反引号 | **匹配点之前的全文**（危险！） | 原样显示（`$` 和反引号两个字面字符） |
| `$'` | **匹配点之后的全文**（危险！） | 字面 `$'` |
| `$<name>` | 命名组（pattern 里要有 `(?<name>…)`），没有则原样 | 原样输出 |

三句话记住：

1. **preProcess 里要字面 `$` 就写 `$$`**，要捕获组写 `$1`，要整段写 `$&`——**永远不要写「美元符 + 反引号」（它表示匹配点之前的全文）和 `$'`（之后的全文本）**。
2. **inline 里 `$0` 和 `$&` 都表示整个匹配**，`$$` 表示 `$`。
3. **block 模板里除了 `$content`，其它 `$` 都是普通字符**（写 `$1` 就输出 `$1`）。

---

## 3. 数捕获组（`$N` 最容易错）

- 每个 `(` … `)` 算一组；`(?:` `(?=` `(?!` `(?<=` `(?<!` `(?<name>` 中只有 `(?<name>` 算**捕获**组。
- 组从 1 开始编号，`$0` 不是组。
- 用不上捕获的括号写成 `(?:…)`，既省组号又更快。
- 例：`\[\[t:([^\]]+)\]\]` 只有 **1** 组 → 模板里只能用 `$1`。
- 写了 `$2` 而 pattern 只有 1 组：inline 静默变空串 → 用户看到「内容消失」，极难查。

---

## 4. pattern 的 7 条硬约束

1. **终点必须明确**：用 `[^\]]+`、`[^@\n]+`、`[^{}]+`，别用 `(.*)` / `(.+?)` 指望它自觉。行内文本里还藏着占位符（`\u0000N\u0001`），宽泛匹配会吞进去，输出变成乱码。
2. **不要匹配 HTML**：行内规则执行时 `<b>` 之类已被摘走；捕获到的只会是占位符碎片。
3. **不要跨段**：行内规则在单个行内文本块上跑，`\n` 不可靠；围栏才是整块。
4. **不要用 `\p{…}` / `\u{…}`**：inline 规则只带 `g` 标志（没有 `u`），这些写法不会生效。匹配汉字用 `[\u4e00-\u9fa5]`（JSON 里写 `"[\\u4e00-\\u9fa5]"`）。
5. **不要和 Markdown 抢符号**：`* _ ` ~ = $ | [ ] ( ) # > \ !` 优先让给 Markdown；自己定界符用 `[[ ]]`、`@@`、`{{ }}`、`{中文:…}`。
6. **别写能匹配空串的模式**（`(x*)`、`(\d*)` 配 `g`）：会在每个字符位置插入一次，预览直接卡死/炸开。
7. **别写嵌套量词**：`(a+)+`、`(\w*)*`、`(.*)*` 会触发工具告警「可能有灾难性回溯」。改写成 `a+`、`\w+`、`[^\n]*` 这种单层量词。

## 5. 实测可用的配方（直接抄）

### 5.1 行内小标签

```json
{ "type": "inline", "pattern": "\\[\\[t:([^\\]]+)\\]\\]",
  "replacement": "<span class=\"ext-tag\">$1</span>" }
```

`[[t:重点]]` → `<span class="ext-tag">重点</span>`

### 5.2 行内高亮（避开 `==`，用 `@@`）

```json
{ "type": "inline", "pattern": "@@([^@\\n]+)@@",
  "replacement": "<mark class=\"ext-hl\">$1</mark>" }
```

### 5.3 带固定前缀的提示词（捕获组用在文本位）

```json
{ "type": "inline", "pattern": "\\{易错:([^{}]+)\\}",
  "replacement": "<span class=\"ext-warn\"><b>易错</b>：$1</span>" }
```

`{易错:单位要统一}` → `<span class="ext-warn"><b>易错</b>：单位要统一</span>`

### 5.4 两个捕获组 + 属性位插值（合法且安全）

```json
{ "type": "inline", "pattern": "\\[\\[c:(red|blue|green):([^\\]]+)\\]\\]",
  "replacement": "<span class=\"ext-c ext-$1\">$2</span>" }
```

`[[c:red:注意]]` → `<span class="ext-c ext-red">注意</span>`
（`$1` 在引号属性里：运行时会做属性转义；因为捕获值只能是单 token，安全。）

### 5.5 缩写/术语

```json
{ "type": "inline", "pattern": "\\{\\{([A-Za-z][A-Za-z0-9 ,.-]{0,30})\\|([^}|]+)\\}\\}",
  "replacement": "<abbr class=\"ext-abbr\" title=\"$2\">$1</abbr>" }
```

`{{SVG|可缩放矢量图形}}` → 悬停提示（打印时 title 不显示，别把关键信息放 title）。

### 5.6 题号徽章

```json
{ "type": "inline", "pattern": "\\[\\[#(\\d{1,3})\\]\\]",
  "replacement": "<span class=\"ext-qno\">第 $1 题</span>" }
```

### 5.7 围栏：提示 / 警示 / 答案

```json
[
  { "type": "block", "fence": "tb-tip",
    "replacement": "<div class=\"ext-card ext-tip\"><div class=\"ext-card-h\">提示</div>$content</div>" },
  { "type": "block", "fence": "tb-warn",
    "replacement": "<div class=\"ext-card ext-warn\"><div class=\"ext-card-h\">易错</div>$content</div>" },
  { "type": "block", "fence": "tb-ans",
    "replacement": "<div class=\"ext-card ext-ans\"><div class=\"ext-card-h\">答案与解析</div>$content</div>" }
]
```

### 5.8 preProcess：全局省略号（安全的字面替换）

```json
{ "pattern": "\\.\\.\\.", "replacement": "…", "flags": "g" }
```

之所以安全：`...` 在代码里也会出现（如 `obj...args`），但替换成 `…` 只是显示变化；**如果你的文档里有代码块要保留 `...`，就别用 preProcess，改用行内规则**。

### 5.9 preProcess：中文破折号（用环视避开代码标识符）

```json
{ "pattern": "(?<![\\w-])--(?![\\w-])", "replacement": "—", "flags": "g" }
```

`(?<!…)` / `(?!…)` 是零宽断言，不消耗字符，也不会成为捕获组。

---

## 6. 反例（会失败 / 会翻车）

| 写法 | 问题 |
|---|---|
| `"pattern": "\\[\\[t:(.*)\\]\\]"` | `.*` 会吞到本段最后一个 `]]`，多个标签时全挤成一个 |
| `"pattern": "\\[\\[t:(.+)\\]\\]"` | 同上（贪婪）；改用 `[^\]]+` 或 `(.+?)` + 明确右界 |
| `"replacement": "<span class=$1>$2</span>"` | `$1` 裸插属性 → `unsafeTemplate`，整份禁用 |
| `"replacement": "<div title=\"$1\">…"` | 合法（引号属性），但捕获值里的引号会被转义成实体，显示难看 → 捕获值保持简单 |
| `"pattern": "(\\w+)"` + `"replacement": "<b>$1</b>"` | 会把每个词都变粗体（也是性能炸弹） |
| `"pattern": "\\p{L}+"` | inline 没有 `u` 标志，`\p` 不生效 |
| preProcess 的替换串里写「美元符 + 反引号」 | 插入匹配点之前全文，文档瞬间翻几十倍 |
| `"pattern": "(a+)+"` | 灾难性回溯告警 |
| `"replacement": "$1"`（pattern 无捕获组，preProcess） | 原样输出 `$1`（不是空） |
| `"pattern": "\\[\\[t:(.+)\\]\\]"` 放在 block 模板里 | block 模板**不做正则**，写 `$1` 只会输出 `$1` 字面 |

## 7. 怎么确认写对了（别靠想象）

1. 跑 `python scripts/check_ext.py 规则.json`：查语法、组数、`$` 陷阱、`$content` 位置。
2. 在 md2pdf 里「应用扩展」，看状态行是否 `已启用`。
3. 写一段 **demo 文本**（正例 + 边界），粘进编辑区看预览：
   - 正例：`[[t:重点]]`、连续两个标签、标签里带标点、标签在表格单元里、标签在标题里；
   - 边界：只写一半 `[[t:没闭合`、嵌套 `[[t:a[[t:b]]]]`、空 `[[t:]]`。
4. 同样的 demo 用 ` ```tb-tip ` 走一遍围栏（内容里塞列表/表格/公式/图片）。
5. 打印预览看一眼：有没有被切页、颜色够不够深。

> 匹配不到**不会报错**，所以第 3 步不能省——「没生效」大多数时候是 pattern 写错或键名拼错。
